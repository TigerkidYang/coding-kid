# Version 16 Verification

Date: 2026-08-07

## Scope

Version 16 was verified as a general recoverable-autonomy release. No
Terminal-Bench, SWE-bench, paid batch evaluation, task-specific prompt, or
benchmark solution was run or added.

## Deterministic Verification

- Root suite: 485 tests collected, 483 passed, and two Windows symlink tests
  skipped.
- Ruff check passed over `src` and `tests`; all 336 Python files passed Ruff
  format check.
- Ten consecutive stress rounds passed. Every round covered sensitive-effect
  serialization, external-edit rollback conflict detection, and recovery after
  a simulated mid-patch I/O failure.
- V15 source fidelity and the installed V1-V16 launcher registry passed as part
  of the root suite.

Coverage includes required/best-effort/off manifests, full/scoped/none
recovery, Git and non-Git projects, Git absence, large files, file-count and
byte limits, protected paths, nested cwd resolution, symlinks where the host
permits them, V15 manifest compatibility, explicit partial rollback, running
task/Agent refusal, and read-only no-op behavior.

Patch coverage includes add/update/delete, multiple files and hunks, Unicode,
empty files, CRLF, missing final newlines, duplicate and missing context,
invalid markers and paths, protected metadata, sandbox boundaries, zero-change
validation failure, bounded diagnostics, simulated write failure recovery,
exact replace-all, dynamic effect classification, and recovery target
declaration. Loop coverage includes pending and in-progress todo completion,
one soft reminder, typed deferred-plan events, provider `None` collections,
controlled resource-boundary results, persistence, compaction, child Agents,
and existing terminal sessions.

## Packaging

The final wheel contains 308 entries and is 1,131,537 bytes. Inspection found
the V16 `patching.py` implementation and frozen V15 runtime, with no tests,
evaluation sources, caches, or bytecode. A clean Python 3.11 environment
installed dependencies and the wheel. After reinstalling the final wheel, all
V1-V16 commands launched from an unrelated directory and exited before any
provider request.

The permanent standalone V16 teaching archive and annotated tag remain gated
on the user's version-completion confirmation under `docs/VERSIONING.md`.

## Real Installed-Terminal Trials

All trials used temporary projects and the installed wheel.

1. Required/Git: Luna used `apply_patch` for two files, ran two passing
   unittests, called model `diff`, and finished. `/changes` reported full
   coverage. `/rollback` removed Agent edits and generated bytecode while
   preserving a pre-existing dirty Unicode file byte-for-byte.
2. Best-effort/non-Git: a 150 MiB sparse artifact was neither copied nor
   changed. Direct edits received scoped protection; an `execute`-created file
   made recovery partial. Ordinary rollback refused, explicit partial rollback
   restored the protected source, and the shell side effect remained.
3. External-isolation bypass: a disposable Docker container displayed the
   high-risk warning, selected full access with checkpoint off, edited and
   verified a file, rejected application rollback, and was destroyed by
   `docker run --rm`. The existing Python image was reused; dependencies came
   from a domestic PyPI mirror.
4. Todo persistence: one CLI process deliberately ended with a pending item and
   no fatal error. A second process resumed the same session, cleared the item,
   and converged normally.
5. Product TUI: an outer Windows ConPTY rendered the installed full-screen V16
   card, checkpoint and permissions state, accepted `/permissions`, `/changes`,
   and `/exit`, and exited normally.

Live use also found and fixed one product wording defect: checkpoint-off stages
with uncovered effects had been described as having partial rollback even
though rollback was correctly unavailable. They now state that no application
rollback exists.

The first live request used an outdated prefixed model alias and was rejected
before tool execution; the gateway's advertised `gpt-5.6-luna` ID then worked.
Host session evidence retained four final assistant messages and eleven matched
tool calls/outputs; the disposable-container trace adds one short workflow.
Including the rejected request and intermediate tool rounds, no more than 18
short model responses started. Using the prior conservative Luna verification
ceiling, estimated spend remained below USD 0.30 and therefore below the USD
1.00 task limit. Exact per-request cost is not persisted.

## Outcome

V16 implementation, root verification, stress, packaging, installed CLI,
real-model workflows, and real ConPTY checks pass. The implementation is ready
for user completion confirmation; permanent archive creation, independent
archive verification, annotated tag, and normal push follow that confirmation.
